# REQ-20260910-01：CROUS法庭 v1

状态：Frozen（2026-09-10）。延期项必须在对应 Phase 入口前确认，不得改变已冻结的 v1 范围。

## 1. 目标用户

- Télécom Paris、ENSAE 及 Palaiseau 周边学生；
- 熟悉“从夯到拉”网络表达，但不一定知道法语菜名；
- 首轮按桌面端完成 Phase 0–8；移动端上传、投票和布局适配在全部既定阶段之后实施。

## 2. 核心任务

用户打开首页后，应立即能够：

1. 审判一份菜品：赞同当前判决或选择自己认可的等级；
2. 查看主食榜和小菜榜；
3. 上传餐盘照片并完成初判；
4. 在不知道菜名时无障碍提交，由社区补名。

## 3. v1 必做范围

### 3.1 餐厅

- `L’Expérimental`：辅助昵称“宿舍 CROUS / All Suites 附近”；
- `Escoffier`：辅助昵称“学校 CROUS / Télécom 附近”；
- 数据库存正式名称，昵称只用于搜索与显示。

### 3.2 内容模型

- 一次用餐 Meal：整张餐盘与地点、日期；
- 菜品 Dish：可复用的菜品概念；
- 出餐 Serving：某菜在某餐厅某日的实际版本；
- 图片 Photo：属于 Meal，可关联一个或多个 Serving；
- 评价 Vote：用户对某个 Dish 选择的目标等级；不同餐厅和日期的同一道 Dish 共享社区等级。

上传按整盘完成，内部拆为 1 份主食和最多 2 份小菜。主食初判必填，小菜名称与初判均可跳过。

### 3.3 菜名未知

- 菜名不必填；
- 可使用“神秘菜品 #编号”发布；
- 支持用户原始描述、正式法语名、中文名和别名；
- 其他用户可提交名称候选及证据类型；
- v1 不依赖 AI API；
- 现场菜单照片/OCR、AI 看图、外部搜索属于后续增强。

### 3.4 投票

- 投稿者的初判计作第一张真实投票；
- “判得对”保存为当前展示等级；
- “我有异议”必须选择目标等级；
- 每个用户对同一目标仅保留一张有效票，可修改；
- 社区等级按有序等级的中位数计算；
- 展示各等级票数分布、初判、社区判决和总票数。

固定等级（从好到差）：

1. 夯 🐮
2. 顶级 👑
3. 人上人 😎
4. NPC 🤖
5. 拉爆了 💩

### 3.5 排行榜

- 主食与小菜分榜；
- 首页主食榜权重更高；
- 支持按餐厅筛选；
- “今日套餐”只展示某次 Meal，不参与长期单品排名。

### 3.6 去重

- 完全相同文件：哈希拦截；
- 近似图片：感知哈希提示；
- 同餐厅 + 同日期 + 相似名称/图片：展示疑似已有 Serving；
- 用户选择“同一次出餐”“同菜不同次”“完全不同”；
- 系统不得自动合并疑似记录。

### 3.7 身份与治理

- 浏览无需登录；
- 上传、投票、补名、举报需要登录；
- 管理员可隐藏图片、处理举报、合并/拆分记录、确认名称；
- 上传需确认拥有或获准发布照片，避免出现可识别人脸。

### 3.8 赞助

- 外链 Buy Me a Coffee，不在站内处理支付信息；
- 按钮文案：`🤖 给 AI 加个菜`；
- 说明文案：`你的一票决定菜品从夯到拉，你的一欧决定服务器从活着到寄。`；
- 彩蛋：`赞助达到目标后，我们将启用 AI 识菜；再多一点，开发者今晚就不吃 CROUS 了。`

## 4. v1 明确不做

- AI 自动识菜和 OpenAI API 调用；
- 自动抓取 CROUS 每日菜单；
- 好友、关注、私信、勋章；
- 长篇评论与复杂推荐系统；
- 自动无审核合并；
- 完整 Three.js/Rapier 体素场景；
- 多校区、多城市和无限餐厅自助创建；
- 站内支付。

## 5. 核心验收标准

- 首屏无需滚动即可完成一次赞同或异议投票；
- 未知菜名也能在合理步骤内完成投稿；
- 投稿可正确关联餐厅、日期、主食和小菜；
- 修改投票后社区等级与分布正确重算；
- 主食和小菜不会进入同一排名池；
- 疑似重复只提示，不自动覆盖；
- 关闭动画或启用 reduced motion 后全部功能仍可用；
- 桌面端上传和投票可完成；移动端无横向溢出与触控流程验收延期至全部既定阶段之后；
- 未登录写操作被正确拦截；
- 图片和数据库记录可持久化，部署后仍存在。
