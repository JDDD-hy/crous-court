# BIZ-20260910-01：排名、投稿与内容决策

状态：Confirmed（2026-09-10）。

## 1. 已确认方向

### 1.1 初判不是官方结论

投稿者选择一个主观初始等级，它既是冷启动展示位置，也是投稿者的第一张票。后续任何用户只能表达自己的目标等级，不能直接修改“官方等级”。

### 1.2 赞同/反对只是界面语言

- 赞同：提交当前展示等级作为目标等级；
- 反对：打开完整等级选择器，提交用户选择的目标等级；
- 后台永远保存目标等级，不只保存布尔值。
- 同一用户对同一 Dish 只能落槌一次；提交前二次确认，提交后不可修改。“异议”选择当前展示等级时提示其效果与“判得对”相同。

原因：只保存反对无法判断应该上移还是下移；根据不断变化的当前等级递归投票会产生路径依赖。

### 1.3 社区判决

- 等级是有序分类，使用中位数而非平均数；
- 奇数票取唯一中间目标等级；偶数票取两个中间目标等级中较差的一档；
- 同票/边界规则必须由纯函数实现并测试；
- 0–4 票显示“候审中”，5–14 票显示“临时判决”，15 票以上显示“社区判决”。

### 1.4 排名单位

- 社区等级针对 Dish 计算；同一 Dish 在不同餐厅、日期的 Serving 共享票池；
- Serving 保留具体餐厅、日期、照片和投稿初判，Dish 页面必须列出这些上下文，不能伪装成每次出餐都相同；
- 主食与小菜分榜；Meal 仅作为整盘内容展示。

## 2. 菜名治理

每个 Dish 可保存：

- `canonical_name_fr`：标准法语名；
- `canonical_name_zh`：中文名；
- `original_description`：投稿者原话；
- aliases：如 couscous、semoule、古斯古斯、蒸粗麦粉；
- `naming_status`：unknown / suggested / community / verified；
- 候选名称及 evidence：现场餐牌、同日食客、AI 推测、外观猜测。

现场餐牌证据高于图片猜测；AI 结果永远不能用于确定过敏原。

`Dish.original_description` 保留首次建档原话，`Serving.original_description` 保留每次投稿者原话；后续候选、标准名和展示状态不得覆盖这些字段。群众认菜入口使用中文“这到底是什么？”，候选名称本身可保留正式法语菜名。名称旁展示来源状态：`✓ 菜单确认`、`✨ 大概率是`、`👥 群众认领`、`❓ 神秘菜品`、`⚠️ 菜名待审`。

任意登录用户可提交候选并自动成为首位支持者；同一候选达到 3 个不同账号支持后进入 `community`，只有管理员可以进入 `verified`。AI 候选本身不计群众支持票。

## 2.1 案号

- 每张整盘投稿对应一个 Meal 和一个案号；同日投稿不限一张；
- 格式为 `YYYYMMDD-食堂序号-三位当日展示顺序`；Escoffier=`0`，L’Expérimental=`1`；
- 顺序在发布写入时原子分配，不等待审核；隐藏或写入失败造成的空号不回收；
- 案号用于稳定识别，不承诺连续无空缺，也不代表审核优先级。

## 3. 菜品关联决策树

1. 同一账号的规范图片 SHA-256 相同：阻止重复提交；不同账号不互相拦截；
2. 用户主动完成 AI 识别后，按每个已识别主食/小菜的标准名、中文名、原始描述和别名列出最多 3 个带历史照片的已有 Dish；识别前不查询、不展示任意候选；
3. 用户选择“就是它”时复用 Dish，并为本次 Meal 新建独立 Serving；未选择时新建 Dish；
4. AI 可按用户主动请求给出结构化名称候选，但不得自动关联或合并；
5. 管理员可明确合并两个同类别 Dish：迁移 Serving/别名，同一用户冲突票保留创建时间较早者；来源 Dish 记录目标；
6. 拆分只把选定 Serving 移至新 Dish，不复制原 Dish 的社区票；
7. 所有管理操作写审计日志。pHash、视觉 embedding 和聚类延后，以真实标注数据校准后再决定。

每个用户的每次 Meal 是独立观察；Dish 是排行榜身份，Serving/Photo 是其跨用户、跨日期、跨餐厅的“行踪”。

## 5. 风险

- 冷启动：需要 20–50 个有授权的种子条目；
- 刷票：登录、唯一约束和基本速率限制；
- 内容风险：举报、管理员隐藏、EXIF 清除、人脸提醒；
- 个人审阅状态直接复用 Vote：当前账号对 Dish 无 Vote 时可显示 `NEW`，首次投票成功后消失；不新增独立审阅表，也不跨账号推断；
- AI 只承担内容风险初筛与临时隐藏建议，管理员负责恢复、申诉及永久治理操作；AI 不得删除原始数据或自动合并 Dish；
- 样本误导：所有聚合结果显示票数与状态；
- 搞笑越界：只调侃菜品与产品，不攻击厨师、投稿人或群体。

## 6. 账号连续性

邮箱去除首尾空格、仅统一域名部分大小写后生成不可逆摘要；本地部分大小写不同视为不同账号，同一完整邮箱始终复用同一 User ID。退出或会话过期只结束当前登录，不删除投稿、投票或账号映射。不做服务商特定的点号或 `+alias` 合并。
