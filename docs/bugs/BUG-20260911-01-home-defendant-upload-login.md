# BUG-20260911-01：首页被告轮换与投稿登录入口

状态：Fixed pending verification（2026-09-11）。

## 症状

- 首页始终展示首次加载的一个被告，没有轮换或手动切换；
- 未登录点击顶栏“投稿”只导航到上传页，没有弹出邮箱验证码登录提示。
- 投稿弹窗完成邮箱验证后只刷新首页，没有继续进入上传页；客户端导航偶发无响应。
- 顶栏“今日开庭”同样受客户端导航状态影响，点击后偶发不返回首页。

## 根因

- `HomePrototype` 只保存 `meals[0]`，未维护轮换索引；
- `SiteHeader` 使用无条件 `/upload` 链接，且没有接收服务端登录态。
- 投稿专用登录流程没有携带成功后的目标页面，已登录入口依赖客户端路由状态。

## 修复

- 有多个有效 Dish 时每 8 秒循环展示，并提供上一位/下一位按钮；
- 服务端页面把布尔登录态传给顶栏；未登录使用 Dialog 内的邮箱验证码表单，已登录保留普通上传链接；
- 投稿弹窗验证成功后使用浏览器原生导航进入 `/upload`；已登录投稿入口也使用原生链接；
- 顶栏品牌和“今日开庭”使用原生 `/` 链接，确保完整返回首页；
- 投票弹窗、登录框、确认框或提交期间暂停自动轮换；
- 不向客户端传邮箱或 User ID。

## 回归验证

- 首页必须含轮换控件和未登录投稿触发器；
- 构建、单元测试、真实页面点击、投票端到端与三个页面 HTTP 检查必须通过。
