# UI-20260910-01：页面、视觉与动效

状态：Confirmed for v1（2026-09-10）。

## 1. 视觉命题

“CROUS 塑料餐盘 × 游戏排行榜 × 中文互联网抽象审判现场”。

不做高级餐厅、不做米白生活方式杂志、不做默认 SaaS Dashboard。照片保持手机实拍质感，UI 像被反复盖章、涂改和重新排队的食堂公告墙。

## 2. 色彩与材质

- 托盘深蓝/灰：背景与结构；
- 番茄红：反对、下降、拉；
- 蛋黄黄：强调、候审；
- 洗碗液酸绿：赞同、上升、夯；
- 黑白高对比：正文与橡皮章。

五档等级 token 使用低饱和色，并同时显示文字与搞笑 emoji：

| 等级 | Emoji | 建议 token |
|---|---|---|
| 夯 | 🐮 | `#D88C86` |
| 顶级 | 👑 | `#D5B26F` |
| 人上人 | 😎 | `#D4CA78` |
| NPC | 🤖 | `#C4BDB3` |
| 拉爆了 | 💩 | `#B6AAA4` |

等级必须同时使用文字/图形，不只靠颜色。卡片可使用餐券锯齿、油渍纹理、歪斜拍立得与橡皮章，但正文保持清晰。

## 3. 页面结构

顶栏左侧品牌标识进入 `/story`，右侧“今日开庭”返回首页。`/story` 首版仅保留 Our Story 占位与待补内容，不虚构发起人署名或项目经历。

桌面顶栏在“今日开庭”左侧增加“长期榜单”，进入 `/rankings`。首页保留今日被告、悬案与赞助卡，不再重复完整榜单；长期榜单用“主食 / 小菜”标签切换，Dish 的历次 Serving 面向用户称为“被观测”。

### `/` 首页

第一视口直接显示“今日被告”：大图、餐厅昵称/正式名、日期、当前判决、票数、`判得对`、`我有异议`。不得用大型 Hero 挡住投票。

“今日被告”在全部有效 Dish 间每 8 秒轮换，并提供上一位/下一位按钮；用户操作不依赖自动轮播。

下方依次：

1. 主食夯拉榜；
2. 小菜捡漏榜；
3. 最新神秘菜品；
4. 低干扰赞助区。

### `/upload` 上传

流程为照片 → AI 候选（可跳过）→ 菜品信息/已有嫌疑人关联 → 初判 → 发布。“菜品信息”内选择餐厅、日期，并标记 1 主食/最多 2 小菜；名称/别名只提示候选，用户点击后才关联。

餐厅选项显示：

- `🏠 All Suites 附近 — L’Expérimental`
- `🏫 Télécom 附近 — Escoffier`

菜名字段文案：`这是什么？知道就写，不知道交给群众。`

菜名字段默认留空，不显示预设名称下拉；用户仍可自行输入临时名称，并明确“原始文字会保留”。输入名称后显示最多 3 个“疑似老熟人”，用户点击“就是它”才关联已有 Dish。用户可主动点击 `饿晕了？让 AI 指认`，审阅后采用最多 1 主食 + 2 小菜候选；识别失败继续手填或留空。

### `/dish/[id]` 菜品详情

大图、初判、当前社区判决、五档分布、移动历史、不同 Serving/Photo 的“嫌疑人行踪”、名称状态、群众补名和举报入口。

历次照片使用松散拍立得堆叠，但不得依赖滚动动画才能阅读。

### `/me/[id]` 我的内容

我的投稿、我的投票、待处理名称/重复确认。

### `/admin`

举报、待确认菜名、合并记录、隐藏内容及合并/拆分；只对服务端白名单管理员开放，非管理员返回不存在/无权限状态。

## 4. 核心投票交互

默认显示：

- `判得对`：提交当前展示等级；
- `我有异议`：展开五档等级尺。

用户可以点击或拖动菜品卡到目标等级；拖动不是唯一方式，键盘和触屏点击必须可完成相同操作。

提交前显示“法槌没有 Ctrl+Z”的二次确认；提交后两种投票入口均锁定。提交失败时恢复并显示明确提示。“异议”选择当前等级时提醒其效果与“判得对”相同。

未登录点击全站顶栏“投稿”时直接弹出邮箱验证码登录框，并在验证成功后进入上传页；已登录时该按钮直接导航到上传页。

照片选择器接受 JPG、PNG、HEIC 和 HEIF；HEIC/HEIF 转换失败时保留在当前步骤并给出可操作错误，不显示无法兑现的成功预览。

首页和详情页复用同一投票控件；未登录时打开邮箱验证码登录框，不向客户端传递邮箱或 User ID。网页文案不得出现 Phase 编号或内部阶段说明；尚未实现的移动历史、认菜和 AI 功能只显示中性的筹备/空状态，不伪造数据。

已登录用户尚未对某 Dish 投票时，首页今日被告与排行榜卡片使用小型低饱和 `NEW` 票签；未登录不显示。服务端确认投票成功后票签立即消失，详情页继续使用“已封卷”说明。票签只根据当前账号的 Vote 集合生成。

## 5. Codrops 动效映射

### MotionPath：跨等级移动

服务端确认投票成功后，判决章按升降方向沿短弧线落槌；失败或乐观回滚不播放。效果不得阻塞投票状态更新。

### GSAP Flip：榜单洗牌

投票、筛选或社区等级变化后，卡片平滑挤开并进入新位置。不得闪烁、瞬移或丢失焦点。

### Polaroid：历史照片

详情页先完整展示当前证物；存在其他 Serving 照片时，用原生 `details/summary` 展开固定轻微错位的拍立得网格并按日期排列。没有额外照片时显示真实空状态，不重复主证物。

### Pixel 效果

v1 使用 Canvas 2D pixel shatter：仅当菜品一次跨越至少 2 档向下移动，或首次进入“拉爆了”时播放。像素从卡片底部少量碎裂坠落，约 1200ms，结束后销毁 Canvas。

不改变真实图片文件，不遮挡结果，不自动循环，不播放闪烁。

### Three.js / Rapier Pixel Voxel Drop

已纳入合并后的 Phase 7。仅桌面、空闲时延迟加载；移动端和 reduced-motion 完全禁用。未通过性能预算不得合入。

### AI 评分主体标示

上传页 AI 识别成功后，先在同一张本地预览图上按归一化坐标框出全部“主食”“小菜 1”等评分主体；采用候选后，各小菜评分控件旁只重复显示对应主体红框，主食初判区只显示主食红框。换照片或主动清除识别结果时同步清空坐标。不生成、保存或上传多份标注图片；坐标缺失时不画框，用户仍可手动填写和评分。

## 6. 动画强度

| 级别 | 场景 | 时长 |
|---|---|---:|
| 微反馈 | 按钮按压、盖章、hover | 120–220ms |
| 状态变化 | MotionPath、Flip | 550–1400ms |
| 重大判决 | pixel shatter、升级庆祝 | 约 1200ms |

启用 `prefers-reduced-motion: reduce` 时：移除路径、粒子、像素和视差，只保留 0–100ms 淡入或即时更新。

动效默认开启，不在主导航放置开关；操作系统启用 reduced motion 时自动关闭。重大效果按 `Dish + 判决结果` 每个浏览器会话最多播放一次。

## 7. 关键文案

- 未知名称：`今日菜单无人取证，启动全民认菜。`
- 补名入口：`这盘到底是什么？`
- 赞助按钮：`🤖 给 AI 加个菜`
- 赞助正文：`你的一票决定菜品从夯到拉，你的赞助决定服务器从活着到寄。`
- 跳转提示：`去投喂`
- 反转小字：`有了你们的帮助，我就不用再吃 CROUS 了——然后本网站也将因为失去一手信源而倒闭。`

## 8. 响应式与无障碍

- 移动端等级尺未来采用两行或垂直展示；完整移动端适配延期至全部既定阶段之后；
- 触控目标至少约 44px；
- 图片有基于菜名/临时描述的 alt；
- Dialog/Sheet 正确管理焦点；
- 动画后焦点不移动；
- 用户可在设置中关闭夸张动画。

首页“今日被告”证物图完整展示整张餐盘，不使用会裁掉主食或小菜主体的 `cover` 裁切；不同宽高比允许出现托盘色留白。

菜品详情的票数、历史与认菜导航使用细下划线选中态，不使用占满标签栏的大块滑块；按钮仍保留约 44px 点击高度。
